MIT-Stanford LFP/흑연 배터리 데이터에서 **초기 열화 신호와 충전 조건이 수명에 어떻게 연결되는지** 확인하고, 초기 100사이클 정보로 전체 수명(`cycle_life`)을 예측한다. 한 배치에서 보이는 관계가 다른 배치에서도 유지되는지, 수명과 관련된 지표를 실제 초기 예측에 사용할 수 있는지를 함께 판단했다.

## 1. Data Check — 무엇을 수명 예측에 사용할 수 있는가?

먼저 MATLAB 파일이 셀 메타데이터, cycle 요약값, cycle 내부 시계열로 나뉘는지 확인했다. MATLAB v7.3의 HDF5 object reference를 `h5py`로 해제하고, 분석 목적에 맞게 셀 CSV·summary CSV·profile NPZ·전압축 CSV로 분리했다.

| 확인한 사실 | 처리·설계 판단 |
|---|---|
| `barcode`, `channel_id`는 셀 식별 정보이고 `cycle_life`는 최종 수명 | 식별자와 target을 구분했다. 식별자를 수명 설명변수로 사용하지 않는다. |
| 셀 번호는 각 배치에서 다시 시작함 | 통합·병합 키는 `(batch, cell_id)`로 두고 중복과 행 누락을 검사했다. |
| Batch1 상세 시계열의 첫 행은 길이 2의 `[0, 0]` dummy | 실제 dummy임을 확인한 행만 profile 추출에서 제외했다. |
| Batch2·3은 첫 cycle부터 실제 profile이 존재함 | Batch1의 첫 행 제외 규칙을 일괄 적용하지 않고 실제 cycle 1을 보존했다. |
| Batch1은 `summary_last_cycle = cycle_life − 1`; Batch2는 수명이 확인된 39개 모두 마지막 기록이 수명보다 큼 | 기록 길이를 수명으로 대체하지 않는다. 마지막 cycle·전체 기록 길이도 target 정보를 담으므로 예측 입력에서 제외한다. |
| raw V·Qd·T 등은 cycle마다 길이가 다르지만, Qdlin은 공통 3.5→2.0 V의 1000점 축에 대응함 | ΔQ(V)는 공통 전압축에서 비교한다. 행 위치 대신 저장된 실제 cycle 번호로 10·100사이클을 찾는다. |
| 일부 `cycle_life`는 결측이고 IR에 0값이 있음 | 추출 단계에서는 원본 값을 보존한다. 수명 결측은 수명 관계 분석에서 제외하고, IR=0의 발열 계산 여부는 Feature Engineering에서 판단한다. |

따라서 **관측 시점을 먼저 고정하고 그때까지의 정보만 사용해야 한다**고 판단했다. 최종 입력은 충전 정책, 초기 100사이클 평균 측정값, cycle 10·100의 Qdlin에서 만든다. 평균 측정값 계산에서도 첫 cycle의 일곱 측정값이 모두 0인 placeholder만 제외했다.

| 배치 | 전체 셀 | 수명 확인 셀 | 세 지표가 있는 셀 | 모델링 사용 |
|---|---:|---:|---:|---|
| Batch1 | 46 | 46 | 46 | 학습·검증 |
| Batch2 | 47 | 39 | 33 | 테스트 |
| Batch3 | 46 | 44 | 44 | 제외 |
| 합계 | 139 | 129 | 123 | Batch1·2의 79개 셀 |

수명 결측 10개를 기록 길이로 채우지 않았다. 초기 IR 평균이 0인 Batch2의 6개 셀은 이후 발열 근사를 계산하지 않아 모델 입력표에서 제외했다. 짧은 수명 자체는 제거 이유로 삼지 않았다.

## 2. EDA — 발견한 네 가설을 왜 기각하거나 유지했는가?

시각화에서 먼저 **Batch2의 단수명 집중, 특정 전압의 Q 급변, 열화곡선의 knee, 로그 지표와 수명의 음의 관계**를 발견했다. 지표의 특징에 맞게 그룹 분류 또는 회귀·상관으로 확인했다. 여기서 기각은 이번 공통 초기 예측 입력으로 채택하지 않는다는 뜻이다.

| 가설 | 확인한 결과 | 판단과 이유 |
|---|---|---|
| ① Batch2의 단수명을 운전조건으로 구분할 수 있다 | Batch2 Base 30개 중 28개가 단수명이고 `newstructure` 9개에는 단수명이 없다. 하지만 같은 Base인 Batch1에는 단수명이 없고 Batch3에서도 같은 구분을 적용하기 어렵다. | **기각:** Batch2 내부의 구분 기준을 다른 배치에 공통 적용하기 어렵다. |
| ② Q 급변 구간의 크기·변화가 수명과 관련된다 | cycle 10의 dQ/dV 피크 크기는 수명과 r=−0.063이다. 피크 전압 이동량도 전체 r=−0.344이며 배치별 방향이 일정하지 않다. | **기각:** 특정 전압에서 Q가 급변한다는 사실이나 추출한 피크 지표만으로 수명을 충분히 설명하기 어렵다. |
| ③ 이른 knee로 짧은 수명을 구분할 수 있다 | knee를 안정적으로 찾은 127개 셀에서 knee 시점과 수명은 r=0.975로 강하게 관련된다. | **기각:** 이번 knee는 꺾임 이후의 후기 기록을 보고 찾았다. 빠른 열화를 확인한 뒤의 지표라 초기 수명 예측 목적에 늦다. |
| ④ 초기 ΔQ(V) 로그 분산이 클수록 수명이 짧다 | 전체 Pearson r=−0.851, 배치1/2/3은 −0.886/−0.902/−0.702로 모두 음수다. | **유지:** 배치가 달라져도 관계가 유지되고 100사이클 시점에 계산할 수 있다. |

**로그 그래프를 그린 이유:** ΔQ(V)=Q100(V)−Q10(V)의 분산은 약 103배 차이가 났다. 원래 축에서는 작은 값들이 몰려 있어 `log10(분산)`으로 셀 간 차이와 수명 경향을 확인했다. 로그 변환은 크기 순서를 바꾸지 않으며, 수명에는 로그를 취하지 않았다.

**수명과 연결된다고 해석한 이유:** 이 분산은 총용량 감소량보다 전압별 곡선 변화가 얼마나 불균일한지를 표현한다. LFP/흑연 셀의 음극 활성물질 손실 등은 총용량 감소가 뚜렷해지기 전에도 전압 곡선을 바꿀 수 있다. 이런 초기 변화가 누적 열화와 짧은 수명으로 연결될 가능성을 로그 지표의 도메인 근거로 삼았다. [Severson et al. (2019)](https://web.mit.edu/braatzgroup/Severson_NatureEnergy_2019.pdf)

## 3. EDA의 상관관계 — 어떤 변수가 겹치고 무엇을 남길 것인가?

기존 충전 정책·초기 측정값에 새 지표인 로그 분산을 더해 상관관계를 비교했다. **전체 상관이 커도 배치 안에서 방향이 달라지면 공통 수명 신호로 바로 채택하기 어렵다**고 판단했다.

- 로그 지표는 전체와 세 배치 안에서 모두 수명과 음의 관계를 유지했다.
- 1단계 C-rate는 Batch1에서 r=−0.580이지만 다른 배치에서는 관계가 약했다. 2단계 C-rate 단독으로도 관계가 약해, 속도 한 값으로 충전 조건을 설명하기 어렵다고 봤다.
- 평균 방전용량은 전체 r=−0.500이지만 배치별로 +0.193/−0.332/+0.217이었다. 온도·충전시간도 배치에 따라 방향이나 관계의 크기가 달랐다.

독립변수끼리 **|r|≥0.8이면 중복 후보**로 보고, 겹치는 온도 요약값은 수명과의 관계를 함께 고려해 대표 하나를 남겼다.

| 변수 | 결정 | 제거·유지 근거 |
|---|---|---|
| 평균 Tmin | 기본 후보로 유지 | 온도 변수 중 수명과의 상관이 가장 큼: r=+0.332 |
| 평균 Tavg | 제거 | Tmin과 r=0.859로 겹치고, 수명과의 관계는 r=+0.238로 더 작음 |
| 평균 Tmax | 제거 | Tavg와 r=0.880인 온도 묶음에서 수명과의 관계가 r=−0.017로 가장 약함 |

Tmax–Tmin의 r는 0.574다. 따라서 Tmax는 Tmin과의 높은 상관만으로 제거한 것이 아니라, 온도 묶음에서 수명과의 관계가 가장 약하다는 판단도 사용했다.

이 결과를 Feature Engineering에 넘겼다. 기본 후보는 **충전 정책 3개(C1·전환 SOC·C2), 초기 평균 측정값 5개(QCharge·QDischarge·IR·Tmin·chargetime), 로그 지표 1개**다. 이 9개에서 도메인 조합을 검토해 최종 입력을 선택했다.

## 4. Feature Engineering — 충전속도와 SOC 구간을 왜 묶었는가?

처음에는 충전속도나 전환 SOC 자체가 수명과 관련될 것으로 생각했다. 그러나 같은 속도라도 **어느 SOC 구간에서 얼마나 많은 양을 충전했는지**에 따라 부담이 달라질 수 있다. 남은 정책 변수와 초기 측정값을 묶어 이 차이를 표현하려 했다.

정책은 C1으로 전환 SOC까지, C2로 80%까지 충전한다. 이후 1C 구간은 공통이므로 조합 지표는 0~80%의 두 단계로 정의했다. s=전환 SOC/100, 공칭 용량 Qn=1.1 Ah다.

| 검토한 조합 | 확인한 관계 | 선택 판단 |
|---|---|---|
| 전체 충전 부담 | 전체 r=−0.356, 배치별 −0.892/−0.210/−0.449 | **유지:** 속도와 적용 SOC 폭을 결합하고 세 배치 모두 음의 관계 |
| 2단계 충전 부담 | 전체 r=−0.243, Batch3에서는 −0.546 | **대안 후보:** 단계별 부담의 의미는 있으나 이번 세 변수 구성에서는 전체 부담을 선택 |
| 이상적 평균 충전속도 | 전체 r=−0.223, 배치별 방향이 다름 | **보류:** 전체 평균 속도만으로 구간별 부담을 충분히 설명하기 어려움 |
| 충·방전 용량비 | 전체 r=+0.088; 129개 중 111개에서 1을 넘음 | **보류:** 수명 관계가 약하고 정밀한 전하 손실량으로 해석하기 어려움 |
| 저항 발열 근사 | 전체 r=−0.526, 배치별 −0.824/−0.632/+0.012 | **유지:** 전류·SOC 폭·저항을 결합한 물리적 후보. Batch3에서는 관계가 거의 없다는 결과도 기록 |
| 온도·충전 부담 교호작용 | 기존 Tmin과 r=0.999이고 배치별 수명 관계도 다름 | **제외:** 기존 변수와 거의 겹치며 공통 관계도 부족 |

전체 충전 부담은 Batch1에서 C1 단독의 r=−0.580보다 더 뚜렷한 r=−0.892를 보였다. 2단계 부담도 Batch3에서 C2 단독의 r=−0.043보다 뚜렷했다. 전환 SOC가 80%이면 2단계 충전량은 0이므로, C2 값만 볼 때 놓치는 차이를 `C2×(0.8−s)`가 반영한다.

최종적으로 **열화 반응을 관측한 지표, 정책의 부담, 저항을 반영한 부담**이라는 서로 다른 역할을 확인하려고 아래 세 지표를 선택했다.

| 최종 입력 | 생성식 | 담으려는 정보 |
|---|---|---|
| L: `log10_dqv_var` | log10(var(Q100(V) − Q10(V))) | 초기 전압별 열화 변화의 불균일성 |
| F: `charge_stress` | C1×s + C2×(0.8−s) | 충전속도와 그 속도를 적용한 충전량 |
| H: `joule_heat_proxy` | 평균 IR×1.1²×F | 같은 정책에서도 셀 저항에 따라 달라지는 저항 발열 근사(Wh) |

정전류 단계에서는 I=C×Qn, 시간=SOC 폭/C이므로 ∫I²Rdt는 R×Qn²×C×SOC 폭으로 근사할 수 있다. 두 단계의 항을 합한 것이 F이고, 저항을 반영한 것이 H다. H는 실제 총발열 측정값이 아니라 저항 성분의 대리지표다. [발열 근거 논문](https://doi.org/10.1149/1945-7111/ac5ada)

IR 평균이 0인 6개 셀을 발열이 없는 셀로 취급하거나 임의로 채우지 않았다. 세 값이 모두 있는 123개 셀을 `battery_features.csv`에 저장하고, 모델링에서는 이 중 Batch1·2의 79개를 사용했다. 조합 변수의 도메인 근거와 실제 추가 예측력은 모델링에서 구분해 확인하기로 했다.

## 5. 모델 설계 — 왜 회귀이고 왜 Ridge인가?

**회귀를 선택한 이유:** 목표는 배터리가 몇 사이클까지 유지되는지를 예측하는 것이다. 단수명·장수명 경계는 EDA에서 그룹을 비교할 때 사용하고, 모델에서는 중간 수명까지 연속적인 차이를 활용하기 위해 원래 사이클 단위의 `cycle_life`를 target으로 정했다.

**세 변수를 사용하는 방식:** 세 개의 단독 회귀를 만드는 것이 아니라 표준화한 세 지표를 하나의 회귀식에 함께 넣었다.

```text
예측 수명 = b0 + b1×L + b2×F + b3×H
```

계수는 다른 입력을 함께 고려해 학습하며 단독 상관계수를 그대로 넣지 않는다. 초기 관측을 100사이클로 고정했으므로 후기 knee·전체 기록 길이도 사용하지 않는다.

**Ridge를 선택한 기준:** 로그 지표의 직선 경향, 계수로 변수 역할을 설명할 수 있다는 점, 입력 간 중복을 함께 고려했다. F·H는 생성식 일부를 공유하며 EDA 123개에서 r=0.726이었다. Batch1 학습 35개에서는 F–H r=0.928, L–F r=0.946으로 중복이 더 높았다. 세 지표를 함께 유지하면서 큰 계수를 억제하려고 L2 규제를 적용했다.

변수 수가 3개라는 사실만으로 모델을 정하지 않았다. 규제 없는 선형회귀를 기준으로 비교하고, SVR·의사결정나무·앙상블은 곡선 관계나 구간·상호작용을 표현할 수 있는 후보로 검토했다. 이번 구현은 피처의 추가 정보와 선형 규제 효과를 확인하는 선형회귀·Ridge 비교로 구성했다.

또한 **도메인상 의미가 있는 변수가 실제로 예측에 정보를 더하는지** 확인하려고, 같은 셀과 같은 분할에서 L 단독 → L+F → L+F+H를 비교했다. 최종 구성은 앞서 정한 세 변수 Ridge로 두고 각 구성의 효과를 결과에 기록했다.

## 6. 검증 설계 — 배치 안의 성능과 배치 간 성능을 구분한다

같은 충전 프로토콜의 셀이 학습·검증 양쪽에 들어가면 유사 조건을 공유한 검증이 될 수 있다. 따라서 최종 Valid를 프로토콜 단위 Hold-out으로 고정하고, 학습 구간 안의 CV도 프로토콜 그룹 단위로 구성했다.

| 항목 | 설계와 이유 |
|---|---|
| Batch1 Hold-out | `GroupShuffleSplit(test_size=0.2, random_state=42)`. 23개 프로토콜을 학습 18개·검증 5개로 나눠 셀 35개·11개를 확보. 20%는 프로토콜 비율이다. |
| Train CV | 학습 35개 안에서 `GroupKFold(5)`. 각 fold에서도 같은 프로토콜이 양쪽에 겹치지 않도록 검사. |
| 표준화 | `StandardScaler → Ridge` 파이프라인으로 매 학습 fold에서만 평균·표준편차를 적합. 서로 다른 변수 단위가 규제에 미치는 차이를 줄임. |
| α 선택 | `[0.001, 0.01, 0.1, 1, 10, 100]` 중 CV 평균 MAPE가 가장 작은 값 선택. 최종 **α=1**. |
| Batch2 Test | Batch1 학습 35개로 적합한 같은 모델을 검증·테스트에 적용. Batch2 오차로 α를 선택하지 않음. |
| 평가 지표 | MAPE를 기본 지표로 원 논문 목표와 비교하고, MAE·RMSE·예측 편향으로 실제 사이클 오차도 확인. |

Train CV는 α 선택에 사용한 검증 fold의 평균이며, 학습 셀에 다시 예측한 오차가 아니다. Hold-out이 별도 검증을 담당한다. 셀 식별자·배치 번호는 입력에 포함하지 않는다.

## 7. 모델 결과 — 설계한 판단이 실제로 도움이 됐는가?

MAPE(%) = 100×mean(|실제 수명 − 예측 수명| / 실제 수명). 비교 Target은 [원 논문](https://web.mit.edu/braatzgroup/Severson_NatureEnergy_2019.pdf)의 9.1%다.

| 구분 | MAPE (%) | 비고 |
|---|---:|---|
| Train (Batch1 CV) | **8.38** | 5-fold 평균, 표준편차 2.41%p |
| Valid (Batch1 Hold-out) | **9.84** | 고정 검증 11개 셀 |
| Test (Batch2) | **45.03** | 배치 간 평가 33개 셀 |
| Gap (Train-Valid) | **+1.46** | Valid − Train CV; 과적합 검토 |
| Gap (Valid-Test) | **+35.19** | Test − Valid; 배치 간 일반화 저하 |
| Gap (Target-Test) | **+35.93** | Test − 9.1; 목표보다 큰 오차 |

Gap의 단위는 **%p**이며 양수는 뒤 평가의 오차가 더 크다는 뜻이다. Hold-out MAE는 **94.27사이클**, RMSE는 **117.75사이클**이고, Batch2는 각각 **215.03사이클**, **224.87사이클**이다.

| 모델 / 입력 | α | Train CV MAPE (%) | Hold-out MAPE (%) |
|---|---:|---:|---:|
| Ridge / L | 1 | 7.51 | 11.24 |
| Ridge / L+F | 1 | 8.31 | 9.75 |
| **Ridge / L+F+H** | **1** | **8.38** | **9.84** |
| 선형회귀 / L+F+H | 규제 없음 | 9.53 | 10.17 |

- **충전 부담의 추가 정보:** Hold-out MAPE가 11.24%에서 9.75%로 줄었지만 CV 평균은 나빠졌다. 추가 효과는 검증 분할에 따라 달랐다.
- **발열 근사의 추가 정보:** Hold-out MAPE가 9.75%에서 9.84%로 소폭 늘었다. 물리적 근거로 선택한 변수지만 이번 모델에서 추가 예측력은 확인되지 않았다.
- **Ridge 규제 효과:** 세 변수 선형회귀보다 CV·Hold-out 오차가 작았고, fold 간 MAPE 표준편차도 4.13%p에서 2.41%p로 줄었다.
- **배치 간 일반화:** Batch1 학습 수명은 534~1227사이클로 단수명이 없지만 Batch2 테스트에는 단수명 26개가 있었다. 이들의 수명을 평균 **230.38사이클 과대 예측**했다. 전체 Test 편향도 +187.99사이클로, EDA에서 확인한 배치별 수명 분포 차이가 실제 예측에서도 문제로 나타났다.

![실제 수명과 Ridge 예측 수명](outputs/model_predictions.png)

간단한 해석 범위: 상관관계와 회귀계수는 열화 원인을 확정하지 않는다. Batch2는 앞선 EDA·피처 검토에 사용됐고 원 논문과 셀 구성·분할·입력이 달라, 9.1%와의 Gap은 과제의 참고 비교다.

## 8. 최종 점검 — 재현성·누출·평가·일반화

| 점검 항목 | 확인 내용 |
|---|---|
| 재현성 | 무작위 프로토콜 분할은 `random_state=42`. GroupKFold는 shuffle 없이 동작하며, 현재 Ridge·선형회귀 학습과 피처 계산에는 무작위 샘플링이 없다. 실행 종료 시각·Python/주요 라이브러리 실제 버전·requirements SHA-256·모델 입력 파일 SHA-256·분할 셀을 `model_metrics.json`에 저장한다. 이전 원본·추출 파일 스냅샷은 과거 탐색 기록에 보존하고, 이번 최종 입력 스냅샷은 모델 실행 시점에 기록한다. |
| Data Leakage | 표준화보다 먼저 Batch와 프로토콜을 분리하고, CV 안에서도 Pipeline이 fold train에서만 scaler를 fit한다. 피처는 셀별 1~100사이클의 고정 계산식으로 만들며 전체 데이터에서 기준값을 학습하지 않는다. 같은 셀의 cycle 행을 무작위로 나누지 않고 한 셀을 한 행으로 사용한다. Batch1→Batch2 평가로 배치 시점 순서를 유지하고 후기 knee·최종 기록 길이·target 파생 입력은 제외한다. |
| Honest Evaluation | α와 후보 비교는 Batch1에서 수행하고, 고정한 모델의 Batch2 결과로 재튜닝하지 않았다. 실행을 반복할 때는 같은 설정의 재현 검사로만 사용한다. Batch2를 앞선 EDA·피처 선택과 과거 탐색에 활용했으므로, 완전히 미관측인 최종 test라고 주장할 수는 없다. 별도의 미관측 배치에서 확인할 사항으로 남긴다. |
| Generalization | 샘플링·수명별 재가중 없이 관측 분포를 평가했다. 단, IR=0인 6개가 제외된 Batch2 33개 기준이며 전체 39개의 성능은 아니다. Train–Valid +1.46%p보다 Valid–Test +35.19%p가 커 배치 간 분포 차이가 주요 문제로 나타났다. 목표 9.1%를 달성하지 못했고 발열 변수의 추가 효과도 확인되지 않았다. |
| Monitoring | 이번 과제는 오프라인 평가다. 운영한다면 초기 100사이클 입력이 쌓일 때마다 세 지표의 분포·결측률·충전 정책 범위를 학습 기준과 비교하고, 실제 수명이 확정된 셀로 월별 MAPE·MAE·편향을 확인한다. 미관측 정책/입력 범위 또는 기준 검증 MAPE보다 5%p 이상 높은 오차가 두 평가 기간 연속 나타나면 데이터 검토와 재학습을 시작하는 잠정 기준을 둔다. 재학습 모델은 새로 확보한 평가 셀에서 검증한 뒤 채택한다. Live Test와 자동 모니터링은 구현하지 않았다. |

과거 탐색 기록인 `outputs/model_selection_manifest.json`은 이전 후보의 이력으로 표시했다. **이번 제출 모델·점수·재현 정보의 기준은 `outputs/model_metrics.json`이다.**
